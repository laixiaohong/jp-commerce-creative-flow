# 中文使用指南

## 1. 准备最少信息

告诉 Codex：产品名称、具体版本/套装、目标渠道、资料链接或文件、这次做到哪一步。

不清楚的写“待确认”。飞书授权成功不代表文档已读取；必须确认返回了需要的内容。实际产品资料保存在私有项目中，不放入这个公开仓库。

## 2. 三种常用说法

### 新项目：先核对事实

```text
$jp-commerce-content-flow
为 XXX 的水箱版套装制作 Amazon JP 页面。
资料：［链接或文件］。
先完成 Source Intake 和 Product Truth Packet，列出冲突、缺口与未批准 Claim。
停在 Product Truth Human Review Gate，不执行视觉生产。
```

### 老项目：接着做

```text
继续 XXX 的 Amazon JP 项目。
先加载现有项目状态与批准记录，告诉我已完成、未解决和下一步。
沿用已批准且适用于当前渠道的基线，不重新批准事实或视觉。
这次只完成［页面策划 / 某张副图修改 / Demo 检查］。
```

继续的前提是旧项目文件可访问；仅有聊天记忆或项目名时不能声称恢复了正式状态。

### 审核后：限定下一步

```text
我确认［具体文件 / 版本 / 审核对象］的［具体决定］。
仅推进到［下一 Gate］，不代表批准其他 Claim、素材、发送或发布。
```

## 3. 应该看到什么

| 当前步骤 | 交付内容 | 需要你判断 |
|---|---|---|
| 资料与事实 | 来源、产品/套装范围、事实包、冲突与缺口 | 哪个版本与事实基线可使用 |
| 页面策划 | 消费者问题、信息顺序、Gallery / A+、素材需求 | 结构和表达方向是否成立 |
| 视觉生产 | 按已批准计划产出的候选素材 | 具体候选是否接受；不是自动证据通过 |
| 最终验证 | 精确文件证据、页面 Demo、QA 与未解决问题 | 是否通过对应审核；发布另行授权 |

缺少工具、权限或证据时，结果可以是 BLOCKED / 待确认，不应伪造完成。

## 4. 只有本仓库，没有统一入口怎么办

使用 `$jp-commerce-creative-flow` 替换上述入口，其他项目说明不变。保留本仓库及 Overlay 可访问，按 [操作手册](OPERATIONS.md) 配置环境。

本仓库自带包装入口和五个上游模块，不自带 Marketing AI Workspace 的统一入口、完整 Product Knowledge 或 Feishu MCP 服务。不要重复安装五个内部模块并要求普通同事逐个调用。
